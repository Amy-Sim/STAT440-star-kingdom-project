# G17：Public 79.17Mの修理・交換計画の作り方

[English](G17_METHOD.en.md) · [提出CSV](G17_single_merge.csv) · [公式年間内訳](evidence/official_G17.csv)

この説明は、Public **79,168,928.88ドル（79.17M）**を記録した **G17** のものです。当時の最良案として呼んでいた版を対象とし、その後の候補とは区別します。

処理の流れは、**管の情報 → F168による漏水時期予測・CMS001による漏水時の修理費予測 → 費用を考慮した工事順 → 円の移動・分割・統合 → 提出CSV**です。

F168は「いつ漏れそうか」、CMS001は「漏れたら修理にいくらかかりそうか」を予測します。その結果を使って交換を急ぐ管を決め、最後に「どの管を一つの円で交換すると安いか」を探索します。

## 1．入力データを準備する

1. 管IDで管の台帳と過去の漏水記録を結合します。台帳は43,039管、修理費モデルの最終学習には2019～2026年の漏水14,113件を使います。
2. 座標はメートルとして扱い、両端を結んだ直線長や周辺の特徴量を計算します。平面上の交差だけでは物理的な接続とは判断しません。
3. 各年の予測には、その年の開始前に分かる情報だけを使います。過去の漏水で交換済みの管も在庫状態に反映します。元からPU、または交換済みの管には交換優先度を付けません。
4. 「漏水後の修理費」と「計画工事の交換費」は別に扱います。`train.csv`の修理費を、円の工事費としてそのまま使うわけではありません。

## 2．予測モデル①：CMS001で「漏れた場合の修理費」を予測する

### 手順A1：性質の違う三つの回帰モデルを学習する

| モデル | 学習するもの・役割 |
|---|---|
| CatBoost | 修理費をドルのまま予測。非線形な関係やカテゴリ間の組み合わせを扱う。 |
| Random Forest | `log(修理費)`を予測し、保存済みの平均補正を行ってドルに戻す。 |
| LightGBM | `log(1 + 修理費)`を予測し、保存済みの平均補正を行ってドルに戻す。 |

各モデルは、それぞれ選ばれた特徴量・前処理を保持します。基礎モデルでは管の属性、地表、年齢・幾何情報、利用可能な過去の集計などを扱います。統合部分の入力は、三つのドル建て予測値と材質・地表の区分です。

対数予測を単純に指数変換するだけでは、ドル建ての平均修理費には戻りません。このずれを補うのがRFとLightGBMの平均補正です。

### 手順A2：過去で学習し、その後の年を予測する

基礎モデルを以前の年で学習し、後の年を予測します。この「学習に使っていない年への予測」を時系列OOF予測として保存します。混ぜ方はこの予測と実際の修理費を使って学習します。例えば2025年を予測するときの混合比には、2023～2024年のOOF結果を使い、2025年の正解は使いません。

### 手順A3：全体の混合比と、材質×地表ごとの混合比を作る

まず、過去OOFのドル誤差の二乗和が小さくなるように、三つのモデルの比率を求めます。比率は負にせず、合計を1にします。

次に、過去OOFが50件以上ある「材質×地表」の組み合わせでは、その区分専用の比率も求めます。ただし少数データに寄りすぎないように、全体比率と混ぜます。

```text
実際に使う比率 = n/(n + tau) × 区分専用の比率
               + tau/(n + tau) × 全体の比率
修理費予測 = 三つのモデルの予測額 × それぞれの比率 の合計
```

`n`はその区分の過去OOF件数です。50件未満や未知の区分では全体比率を使います。`tau`は0、50、200、1000、1e9から、それ以前の時系列検証で選びます。検証年が不足するときは既定値を使います。

**2027年用の最終版**は、基礎モデルを2019～2026年のデータで再学習し、2023～2026年のOOF 8,592件で混合比を求めています。区分別比率の対象は18区分、`tau = 50`です。全体比率は **CatBoost 68.6270%、平均補正log RF 31.3730%、平均補正log LightGBM 0%**です。ただし区分別ではLightGBMの比率が正になる場合があり、すべての管がこの全体比率になるわけではありません。

**例：**ある区分に100件あり`tau = 50`なら、区分専用の比率を2/3、全体比率を1/3使います。これは仕組みを説明する仮の件数です。

## 3．予測モデル②：F168で「いつ漏れそうか」を予測する

### 手順B1：漏水までの時間を十種類のモデルで学習する

各年の開始時点でまだ漏れていない管を対象に、その後の初回漏水を学習します。観測終了まで漏れなかった管は「永久に漏れない」とせず、そこまで生存した観測として扱います。

| 基礎モデル | 主な役割 |
|---|---|
| Elastic-net Cox | 正則化した比例ハザードモデル |
| Weibull AFT、lognormal AFT | 異なる二つの寿命分布を使う |
| Spline survival | 年齢・時間の柔軟な変化を扱う |
| Random survival forest | 木を使った生存予測 |
| XGBoost AFT | 勾配ブースティングによる寿命予測 |
| CatBoost hazard | 年ごとの条件付き漏水確率を予測 |
| MTLR、DeepHit | NNを使った離散時間の生存予測 |
| Hierarchical hazard | 全体と設置年代などのグループ効果を扱う |

モデルごとに選ばれた特徴量は異なります。材質、地表、長さ、年齢、設置年・年代、材質×設置年代、位置・近隣構成、**過去だけから集計した**周辺・年代別の漏水履歴などを使います。採用されたモデルでは50m・100m・250mの近隣集計も使います。全モデルが全特徴量を使うわけではありません。

### 手順B2：十個の予測をRidgeで統合する

F168は`optuna_base`の基礎モデルを使い、**標準化 → Ridge回帰**で統合します。単純な十モデル平均ではありません。

2027年用では、2020～2026年の「過去で学習して翌年を予測した結果」と実際の漏水有無を統合学習に使います。Ridgeの正則化の強さは、以前の年で学習し、利用可能な直近年で検証して選び、その後すべての利用可能な年で学び直します。最終設定は **alpha = 7308.877234445037**です。

Ridgeの係数には「すべて非負・合計1」という制約はありません。CMS001の混合比とは仕組みが異なります。以前の設置年ごとの手動確率上書きは使いません。

### 手順B3：25年分の生存曲線にする

各基礎モデルの生存曲線を年ごとの条件付き漏水確率に変換し、各年に同じRidgeの統合式を適用します。統合結果を0～1に収め、生存確率を計算します。

```text
h(t) = t年目まで生き残った管が、その年に漏れる確率
S(t) = 1年目からt年目までの (1 − h) の積
F(t) = 1 − S(t) ＝ t年以内に漏れる確率
```

基礎モデルの観測可能な期間を超える部分では、最後のハザードを一定として延長し、上限0.95にします。これは将来への外挿の仮定です。

**例：**1年目の漏水確率0.10、1年生存した後の2年目の漏水確率0.20なら、2年後まで生存する確率は`0.9 × 0.8 = 0.72`、2年以内の漏水確率は0.28です。

## 4．二つの予測を混ぜ、工事の順番を作る

出発点は、保存済みの **CMS001＋F168／02_OVERLAP_CREDIT** の順番です。単に漏水確率順、修理費順に並べたものではありません。

### 手順C1：各管に「先に交換する価値」を付ける

`L`を長さ、`C_raw`をCMS001の予測修理費とすると、実装の式は次の通りです。

```text
F2  = 1 − F168の2年後までの生存確率
F25 = 1 − F168の25年後までの生存確率
R   = (1 − 0.3227327995) × F2 + 0.3227327995 × F25
C   = C_raw / (max(L, 0.1) / 未交換管の長さ中央値)^0.0030795309
V   = R^0.8300158668 × max(C − 0.9780439932 × 200 × L, 0)^0.8780168139
```

近い将来と長期の漏水リスクを混ぜ、修理費の大きさと交換する長さの費用を考慮します。`V`は順位用の点数で、ドル建て期待利益そのものではありません。式の定数は保存済みの計画パラメータであり、予測モデルの学習済み混合比とは別です。元からPUや交換済みの管は0点です。

例えば「漏れやすく、漏れたときの修理費が高い管」は先にしやすく、「長くて交換費が高いのに回避できる修理費が小さい管」は後にしやすくなります。基本的な期待損失は「漏水確率×漏水時修理費」で理解できますが、実際の保存済み順序には上の調整式を使っています。

### 手順C2：各円で新しく交換する管を取り出す

1. 両端が円内にある管をすべて調べます。
2. 元からPUの管、過去の漏水で交換済みの管を除きます。
3. すでに選んだ前の工事で交換される管も除きます。
4. 残った管だけを、その工事の新規交換対象にします。

**例：**ある円にA・B・Cが入り、Aは元からPU、Bは前の工事で交換するなら、この円で新しく交換するのはCだけです。優先度の分子に加える価値と、長さに応じた交換費はCについて計算します。

### 手順C3：円の優先度を計算し、選ぶたびに更新する

```text
優先度 = (新規交換対象のVの合計 + 0.01 × 重複円の固定費削減クレジット)
         / 現在の工事費^0.8490093179
```

クレジットは「この工事を先にすると、別の円の未交換管がなくなり、その円を無料で飛ばせる」場合の固定費です。優先度の高い円を選び、その管を交換済みとしてから、重複する円と周辺の依存関係の点数を更新します。

保存済みレシピには局所的な順番移動やブロック移動も含まれます。最後のoverlap-credit段階では、予定年の早いグループから処理し、同じ予定年内でこの優先度を比較します。

### 手順C4：予算で順序を再生する

毎年1,000万ドルと繰越残額を使い、先頭の円から施工します。先頭の工事を支払えない場合は翌年の先頭へ持ち越します。予測を使って事前に順番を作り、提出するのは固定CSVです。実際の漏水ごとにモデルを再学習して並び替える仕組みではありません。

円を変更すると費用が変わり、年の区切りもずれるため、変更後は計画全体を再生して予算・期限を確認します。

## 5．円の場所と大きさを決める

G17は、管ごとの半径を回帰モデルで直接予測していません。**施工可能な円を複数作り、費用を比較して選ぶ探索方式**です。

### 手順D1：工事費を正しく計算する

交換が必要な円の費用は次の通りです。

```text
面積 = pi × 半径²
地表単価 = 円に完全に含まれる全物理管に現れる、異なる地表種類の単価の合計
工事費 = セントに丸める(100 + 地表単価 × 面積^0.85 + 200 × 未交換管の合計長さ)
```

| 地表 | 単価 |
|---|---:|
| grassland | 3 |
| farmland | 7 |
| swamp | 12 |
| road | 17 |
| structure | 50 |
| water | 32 |

0.85乗するのは面積だけです。地表の集計には、交換済みの管も含みます。ただし円内が全部PUなら工事自体を無料でスキップします。

**例：**草地と道路の管を含む円の地表単価は`3 + 17 = 20`です。道路の管が交換済みでも、ほかに交換対象が残っていれば道路分を落とせません。対象の管を覆ったまま中心を動かして道路管を外せれば、単価を3に下げられます。逆に、円をまとめて施工回数を減らしても、高い別地表を巻き込めば損になる場合があります。

### 手順D2：円を縮め、動かし、分ける

1. 元の順序を将来漏水なしで再生し、各行の新規交換対象と予定年を記録します。対象集合を守って円を変え、無関係な未交換管が新たに入る候補は除きます。
2. 1管なら、まず両端の中点を中心に、長さの半分に小さな余裕を足した円を作ります。その管の垂直二等分線上で中心を動かし、別の管が入る・外れる境界付近も比較します。
3. 複数管なら、全対象管の両端を覆う最小包含円、端点平均、端点の外接長方形の中心、旧中心から探索します。各中心で、最も遠い対象端点までの距離に`1e-6m`を足して半径を決めます。
4. 周囲24方向・複数の移動幅を試し、安い中心の近くをさらに細かく探索します。出力時は座標を小数点以下9桁に丸め、端点包含を確認します。
5. 対象2～12管では、1管ずつの施工や、x/y順で区切る二分割も比較します。合計工事費が1ドルを超えて下がる場合に分割します。大きいという理由だけで分割はしません。

### 手順D3：近隣の工事をまとめる

G17に至る開発では、探索範囲を段階的に広げました。

| 段階 | この系統で使った探索 |
|---|---|
| G04 | 同じ予定年の近隣2～3円。対象の和集合は最大10管。 |
| R01 | 中心を二次元でさらに細かく調整。 |
| G05 | 最大6円・16対象管。密集度に応じて近隣探索距離を変更。 |
| G08 | 適応的な近隣探索距離を最大350mへ拡大。候補は最大16円・48対象管。同じ予定年に限定。 |
| G17 | G08に、追加で選んだ1組の統合だけを反映。 |

これらは探索の上限です。常に16円を統合するわけでも、半径350mにするわけでもありません。G08で採用された統合は21件、実際の組は2～6円で、統合後の最大半径は約33.36mでした。

統合候補は次の順で評価します。

1. 候補の各円で新しく交換する管を集め、重複を除いた和集合を作ります。
2. その全端点を覆う円を探索します。予定外の未交換管が入らないか確認し、入っている全管の地表から工事費を計算し直します。
3. 元の円を別々に施工する固定費と、まとめる固定費を比較します。
4. ただし予定年までに漏水して交換済みになれば、その工事は無料で飛ばせます。F168から各管が予定年まで未交換で残る確率`p_i`を取り、`工事が必要な確率 = 1 − product(1 − p_i)`で近似します。この積には独立仮定を使います。
5. `旧円ごとの「必要確率×固定費」の合計 − 新円の「必要確率×固定費」`を求め、期待固定費が下がる候補を残します。同年の同じ対象集合を比べる局所計算では、交換長さの費用は共通です。
6. 同じ旧円を二重に使わないよう候補を選び、統合円を組の最初の行に置き、残りの行を削ります。最後に全体の実行可能性を再確認します。

統合すると、「片方だけがPUになったので無料で飛ばす」という機会が減ることがあります。したがって半径や100ドルの基本料だけで採否は決めません。

### 手順D4：G17で実際に追加した統合

G17は、G13の開発探索に記録された2番目の統合だけをG08へ反映したものです。G08の実施工部分の**行6354と7575（0始まり）**を統合しました。両方とも予定年は2030年です。

元の半径は約**1.897mと10.539m**。統合後は草地の7対象管を含み、半径は**10.539m**です。大きい方の円でまとめて覆えるため、半径を増やさず一つの工事にできました。局所的な期待固定費削減は約**113.66ドル**でした。

実際のPublicではG08より**123.56ドル**改善しました。公式の修理費合計は同じで、差は工事費です。一方、確認シミュレーションではG08に対する一貫した内部優位は確認できていません。この僅差だけで将来も優れるとは判断しません。

### 手順D5：元の幾何カバーを末尾に残す

必要な全鉄管の幾何カバーを満たすため、元のカバー円を実施工の後ろに置きます。その円の管が前の工事ですべて交換され、末尾ではPUだけになって無料で飛ばせることを確認します。末尾に円があること自体は、修理が失敗したことを意味しません。

出力CSVを読み直し、全端点の被覆、施工順、予算、期限も検査します。
